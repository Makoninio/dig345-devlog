1. Reflection ✏️
    <Aside title="Reflection">
        Open Source Atlas as a project seeks to explore open source software as an ecosystem rather than by traditional metrics
        and visualize this uniquely to generate new meaning for users. Open source challenges the idea that software must be proprietary, 
        paid for, or built inside a company. Many of the tools developers rely on every day are created by distributed communities who 
        choose to build in public. This project asks the questions what kinds of work does the open source community seem to value 
        most?

        Beginning with an analysis of the 500 most popular GitHub repositories using data collected from the GitHub API, I collected 
        information on the name, creator, stars, forks, contributors, year created, story fields, and classification 
        scores. I chose to categorize the repositories into an atlas of different islands. Each island represents a different kind of 
        open source function, including infrastructure, utility, startup-oriented tools, viral projects, creative software, learning resources, and ambitious but less visible work.

        The atlas/map metaphor became central to the project’s identity. Early iterations experimented with more traditional layouts such as graphs, 
        but the final direction moved toward a vintage map because it better communicated exploration, discovery, and 
        interpretation. The map functions partly like a scatterplot, with the x-axis representing time to value and the y-axis 
        representing ecosystem impact, but the layout is intentionally more organic. Repositories are grouped into islands so 
        the visualization feels like a navigable landscape rather than a rigid chart.

        The categories are interpretive rather than absolute. Many open source projects overlap in purpose, audience, and function,
         so the atlas should be read as one possible way of understanding the ecosystem.
    </Aside>
